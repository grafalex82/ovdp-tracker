# Трекер ОВДП

Небольшой пет-проект для личного учёта облигаций внутреннего государственного займа Украины (ОВДП). Помогает отслеживать покупки, погашения и прибыль, а также планировать будущие вложения.

Планируемые возможности:

- Добавление облигаций с датой покупки, стоимостью, количеством и датой погашения.
- Учёт полученных выплат и расчёт ожидаемой прибыли.
- Статистика прибыли и доходности за выбранные периоды.
- Планирование будущих покупок и ожидаемых поступлений.

Проект рассчитан на одного пользователя. Приоритет — простые и понятные решения, минимум зависимостей и архитектуры, только необходимой для текущих задач.

## Текущее состояние

Реализован минимальный каркас Flask/Jinja: главная страница, локальный CSS и
схема SQLite версии 3 для банков, общих выпусков ISIN и их календарей, покупок,
фактических выплат и продаж,
точный разбор денежных строк до сотых и вычисление сумм операций.
Форма покупки сохраняет выпуск, его расписание и отдельную покупку одной транзакцией.
Повторная покупка использует тот же выпуск и календарь; конфликтующие общие сведения отклоняются.
На главной странице доступны покупки с группировкой по ISIN, отдельные карточки
с общим календарём и закрытая история. Продажи, подтверждения выплат через интерфейс
и расчёты доходности пока не реализованы.

Первый запуск создаёт пустую базу `instance/portfolio.sqlite3` в корне проекта,
без демонстрационных операций. Файл данных исключён из Git. Повторный запуск
сохраняет данные. При неизвестной версии схемы приложение отказывается от запуска
с объяснением причины и не перезаписывает базу.
При размещении проекта в `D:\Projects\OVDPCalculator` полный путь данных —
`D:\Projects\OVDPCalculator\instance\portfolio.sqlite3`; он не зависит от текущего
каталога запуска. Правило `instance/` в `.gitignore` исключает весь каталог данных.

## Пересоздание базы разработки при переходе на схему 3

Схема 3 несовместима с версиями 1/2: выпуск хранит справочные параметры НБУ,
а каждая плановая выплата — собственную сумму на одну бумагу. Общего поля купона выпуска нет.
В рамках задачи 2.3 база разработки пересоздана пустой после проверки новой структуры.
Все прежние данные разработки разрешено потерять; миграция и перенос истории не реализуются.

При работе с другой старой копией базы, данные которой можно удалить, остановите
приложение через `Ctrl+C`, затем из корня проекта выполните:

```powershell
Remove-Item -LiteralPath .\instance\portfolio.sqlite3
python -m ovdp_calculator
```

Удаление файла безвозвратно удаляет все его данные. После запуска создаётся пустая схема 3.
Обычный запуск не сбрасывает данные автоматически: совместимая база сохраняется,
версия 1/2 или другая несовместимая версия вызывает `SchemaVersionError`, оставляя файл неизменным.

## Установка и запуск

Требуется Python 3.11 с pip. Команды выполняются из корня проекта, например
`D:\Projects\OVDPCalculator`. Создавать virtualenv или устанавливать Docker не нужно.

Установите зафиксированные зависимости в используемый Python:

```powershell
python -m pip install -r requirements.txt
```

Для первоначальной загрузки зависимостей нужен интернет. После установки приложение
сохраняет локальные просмотр и расчёты без интернета. Автозагрузка нового ISIN требует доступа к НБУ.
Шаблоны и стили находятся в пакете; CDN не используются.

Запустите приложение:

```powershell
python -m ovdp_calculator
```

Откройте [http://127.0.0.1:5000/](http://127.0.0.1:5000/) в браузере. Должна появиться
страница «Трекер ОВДП» с действующими покупками и действием «Добавить облигацию».
Сервер слушает только `127.0.0.1:5000`; debug, интерактивный отладчик и автоматический
перезапуск выключены, в том числе при заданной переменной `FLASK_DEBUG`.

Чтобы завершить работу, нажмите `Ctrl+C` в терминале с запущенным приложением.

## Добавление покупки

На главной странице выберите «Добавить облигацию» и режим «Подтянуть из НБУ» или «Ввести вручную».
В режиме НБУ введите полный ISIN: форма автоматически
загрузит валюту, номинал, дату выпуска/первичного размещения, погашение, номинальную ставку,
купонный период в днях, вид облигации и полный календарь выплат из
[официального JSON API НБУ](https://bank.gov.ua/depo_securities?json).
Сервер ищет точный `cpcode` с категорией `DCP`; запрос ограничен 10 секундами,
каждый поиск облигации выполняет новый запрос к НБУ без кеширования. Дополнительные зависимости не нужны.

Суммы берутся непосредственно из `payments[].pay_val` и хранятся для каждой даты отдельно.
Номинальная ставка справочная: по ней не вычисляются купоны или доходность покупки.
Даты не генерируются прибавлением периода. Общее число купонов вычисляется из полного календаря,
включая прошлые и нулевые купоны; погашение в это число не входит. Права покупки и оставшееся
число купонов будут рассчитываться отдельно в задаче 4.1.
Купон и погашение одного дня остаются отдельными событиями. Поддерживается одно обычное
или досрочное погашение; неподдерживаемый график с несколькими погашениями отклоняется целиком.

Разбор данных НБУ отделён от проверки покупки: `parse_bond_data()` возвращает реквизиты
и все выплаты без фиктивных параметров покупки и ограничений формы. Перед заполнением формы
отдельно проверяется поддержка выпуска и календаря; параметры покупки проверяются при сохранении.

Реквизиты НБУ показываются обычным текстом, календарь — таблицей без редактирования.
Дата и цена покупки, количество облигаций и банк собраны в блоке «Параметры покупки»; загрузка их не меняет.
Дата покупки по умолчанию текущая локальная; прошлые даты разрешены, будущие — нет.
Загрузка заполняет только черновик. «Сохранить покупку» атомарно записывает выпуск, календарь,
банк и покупку, затем возвращает портфель с сообщением об успехе.
Ошибка оставляет введённые значения для исправления; частичных записей не остаётся.

Если НБУ недоступен, ISIN не найден или ответ неполный, форма показывает причину.
Выберите «Загрузить повторно» либо переключитесь в режим «Ввести вручную».
В ручном режиме вводятся только номинал, валюта и список купонов с суммами.
ISIN служит идентификатором выпуска; обращения к НБУ в этом режиме нет.
Календарь задаётся строками `ГГГГ-ММ-ДД сумма`, например:

```text
2026-12-01 80,00
2027-06-01 85,00
```

Каждая строка хранит свою сумму на одну облигацию. Купон неотрицательный, номинал,
цена и погашение положительные, денежные значения — максимум до сотых без округления.
Купонные даты уникальны и не позже погашения; даты до покупки сохраняются в календаре.
В ручном режиме погашение определяется последней купонной датой, а сумма погашения равна номиналу.
Для бескупонного выпуска оставьте список пустым: только тогда появится отдельная дата погашения.
Дата выпуска, ставка и тип вручную не запрашиваются. Переключение режимов сохраняет ручной
черновик и параметры покупки; реквизиты НБУ в него не копируются.
Удаление/сортировка отдельных строк редактором предусмотрены в задаче 2.8.

При вводе известного ISIN форма показывает сохранённые общие поля без редактирования.
Ответ НБУ их не перезаписывает; расхождение отмечается предупреждением со ссылкой на
сохранённые реквизиты и календарь. Отдельное общее исправление предусмотрено задачей 3.5.
Повторная покупка сохраняет только свои дату, цену, количество и банк и работает при отказе API.
В ручном режиме известный ISIN проверяется локально: редактор общих полей скрывается,
а сохранённые реквизиты и полный календарь показываются текстом и таблицей.
Выпуск в USD или EUR использует свою сохранённую валюту вместо начального UAH.
После ошибки параметров покупки общие поля остаются недоступны для редактирования,
а введённые дата, цена, количество и банк сохраняются для исправления.
Переданные в обход интерфейса другие валюта, номинал, метаданные, погашение,
дата или сумма любого события отклоняются во всех режимах без записи покупки или нового банка.
Новая дата покупки не обрезает общий календарь, включая прошлые события:
она определяет права этой покупки на выплаты. Расчёт причитающихся сумм реализуется в задаче 4.1.
Изменение ISIN отменяет старую загрузку: запоздалый ответ не может заполнить новую бумагу.
Изменённый черновик защищён штатным предупреждением при закрытии или обновлении страницы;
полная защита внутренних переходов реализуется в задаче 2.7.

## Просмотр покупок

Главная страница `/` показывает действующие покупки с группировкой по ISIN.
У каждой покупки видны банк, дата, исходное и оставшееся количество, цена одной
облигации, точная стоимость покупки с валютой выпуска и погашение. Разные покупки
одного ISIN показаны отдельно с собственными датами, ценами и банками, используя
общие валюту, номинал и календарь с суммами событий. Денежные суммы отображаются с двумя знаками.
Это первый вариант списка задачи 2.2; сводная строка позиции и детали ISIN предусмотрены в 2.6.

Нажмите «Покупка №…», чтобы открыть `/purchases/<id>`. Карточка показывает все
сохранённые параметры, стоимость и остаток, статус и полный календарь выпуска
по возрастанию дат. Купон и погашение в один день остаются отдельными событиями.
Календарь включает сохранённые даты до конкретной покупки; он не является перечнем
её подтверждённых поступлений. Ссылка «Портфель» возвращает на главную страницу.

Ссылка «Закрытые покупки» открывает `/history`: там доступны полностью проданные
и фактически погашенные покупки со своими карточками. На этом этапе продажи
и подтверждения можно сохранять через API `Database`; соответствующие формы будут
добавлены в следующих задачах. Прошедшая плановая дата не закрывает покупку автоматически;
подтверждение погашения одной покупки не закрывает соседние покупки того же ISIN.

Пустые списки объясняют отсутствие записей и предлагают добавить облигацию.
При ошибке сохранения пользователь остаётся в заполненной форме. Просмотр страниц
и перезапуск приложения сохраняют покупки и не создают дубликатов.

## Навигация

Все доступные страницы используют общий шаблон с верхними разделами «Портфель»,
«Выплаты» и «Статистика». Портфель выделен и на вложенных страницах, в том числе
при прямом открытии покупки. «Выплаты» и «Статистика» пока неактивны;
рабочие экраны будут подключены в задачах 4.5 и 6.1.
Действующие и закрытые покупки переключаются внутри портфеля.
«Добавить облигацию» остаётся отдельным действием в списке покупок.

Хлебные крошки показывают положение текущей страницы: «Портфель / Добавить облигацию»,
«Портфель / Покупка №…» или «Портфель / Закрытые покупки».
Родитель «Портфель» ведёт на главную, текущий элемент показан текстом без ссылки.
Путь покупки одинаков при прямом открытии и переходе из действующей либо закрытой истории.
У закрытой покупки дополнительно доступна ссылка на закрытую историю.
Уровень ISIN появится вместе с деталями облигации в задаче 2.6.

## API хранения данных

Класс `Database` из `ovdp_calculator.db` хранит приватное соединение и содержит
SQL, схему SQLite и управление транзакциями. Остальной код получает экземпляр
явно и работает через его методы:

- `add_bank`, `get_bank`, `list_banks`, `delete_bank` — банки;
- `add_issue`, `get_issue`, `get_issue_by_isin`, `list_issues` — общие выпуски;
- `add_lot`, `get_lot`, `list_lots`, `delete_lot` — пакеты;
- `add_scheduled_payment`, `list_scheduled_payments` — плановые выплаты;
- `add_actual_payment`, `list_actual_payments` — подтверждённые выплаты;
- `add_sale`, `list_sales` — продажи.

Класс не зависит от Flask и не использует `g` или контекст приложения.
Методы возвращают обычные словари и списки.
`get_bank`, `get_issue`, `get_issue_by_isin` и `get_lot` возвращают `None`, если запись
не найдена; методы удаления возвращают признак удаления. Плановые события создаются
и выбираются по `issue_id`, фактические выплаты и продажи — по `lot_id`.
`add_bank` обрезает крайние пробелы и повторно использует банк с тем же именем
без учёта регистра.

`add_issue` принимает уникальный ISIN, валюту, номинал, погашение и справочные метаданные выпуска.
`add_lot` принимает только `issue_id`, дату и цену покупки, количество и `bank_id`.
`get_lot` и `list_lots` дополняют записи общими полями выпуска при чтении;
в таблице покупок эти реквизиты не дублируются. `add_scheduled_payment` получает
`issue_id`, тип, дату и точную сумму `amount` на одну бумагу. Купонные даты уникальны внутри выпуска, одно погашение
совпадает с его датой погашения; купон и погашение одного дня — разные события.

`add_actual_payment` требует `lot_id`, `scheduled_payment_id`, фактическую дату
и общую сумму. Составные внешние ключи запрещают событие чужого выпуска;
уникальность пары покупки и события защищает от дубля, сохраняя независимые
подтверждения соседних покупок. Удаление покупки очищает только её продажи и факты,
сохраняя выпуск, календарь и банк даже после удаления последней покупки.
Общее событие с подтверждением нельзя удалить каскадно вместе с фактом.

Каждая одиночная запись сохраняется автоматически. Для атомарного изменения
нескольких записей используется `with database.transaction():`; при исключении
вся группа откатывается. Соединение вызывающему коду не передаётся.
Ошибки ограничений выражаются через `db.DataIntegrityError`, остальные ошибки
SQLite — через `db.DatabaseError`, неизвестная версия — через `db.SchemaVersionError`.
API обеспечивает хранение, проверку формата денежных строк и ограничения схемы; расчёты портфеля и полная
проверка истории относятся к следующим задачам.

Вне HTTP жизненным циклом управляет контекстный менеджер:

```python
from ovdp_calculator.db import Database

with Database("instance/portfolio.sqlite3") as database:
    with database.transaction():
        bank = database.add_bank("Банк А")
```

При выходе соединение закрывается. `close()` можно вызвать явно и повторно;
использование закрытого экземпляра вызывает `DatabaseError`.

Для HTTP под декоратором маршрута добавляется `@with_database` из
`ovdp_calculator.web`. Обёртка создаёт отдельный экземпляр на каждый запрос,
передаёт его первым аргументом обработчику (`def index(database):`) и закрывает
при завершении, включая исключения. Обработчик вызывает методы полученного
объекта. При старте приложение проверяет схему отдельным краткоживущим экземпляром.

## Точность денежных значений

Модуль `ovdp_calculator.money` разбирает денежные строки через `parse_money`
непосредственно в `Decimal`, без промежуточного `float`. Допустимы точка или запятая
как десятичный разделитель, знак и пробелы по краям. Разделители тысяч, экспоненциальная
запись, нечисловые и бесконечные значения отклоняются с `ValueError`; числовые
объекты вместо строк также не принимаются.
Денежные значения допускают максимум два знака после разделителя. Лишние знаки,
включая завершающие нули, отклоняются без автоматического округления:
`1000,01` допустимо, `1000,005` и `1000,010` — ошибка.

Методы `Database` сохраняют номинал, цену покупки, сумму события, цену продажи и фактическую
сумму как точные десятичные строки в полях `TEXT`, с точкой и не более чем двумя
десятичными знаками. При записи исходные значения не округляются.

`operation_amount(unit_amount, quantity=1)` умножает `Decimal` на целое неотрицательное
количество и возвращает точную сумму с двумя знаками после запятой. При цене до
сотых и целом количестве дробных копеек не возникает. Для фактической суммы выплаты
используется количество 1. Агрегаты суммируют точные суммы операций.
В покупках и продажах количество должно быть целым положительным; функция расчёта
допускает также ноль для пустого остатка. Проверка положительности цены и суммы
относится к предметным операциям; денежные функции допускают отрицательные потоки и ноль.

Например, `operation_amount(parse_money("1000,01"), 3)` возвращает
`Decimal("3000.03")` без округления цены или результата.

## Проверки

Средство автоматического тестирования проекта — pytest. Установите зависимости
для разработки (они также включают зависимости приложения):

python -m pip install -r requirements-dev.txt

Для подробного вывода добавьте `-v`, для отдельного файла — `tests/test_db.py`.
Конфигурация запуска хранится в `pytest.ini`. Новые тесты пишутся функциями
с `assert`, фикстурами и параметризацией pytest. Проверки используют временные
SQLite-файлы через `tmp_path` и не меняют рабочую базу.
`tests/test_db.py` проверяет публичный API, общий календарь, независимые подтверждения,
запрет чужого выпуска, атомарность и перезапуск без SQL и контекста Flask.
`tests/test_web.py` проверяет передачу и закрытие экземпляров в HTTP-обработчиках.
`tests/test_purchases.py` проверяет форму покупки, значения по умолчанию, допустимые
валюты и даты, точность сумм, расписание и откат при сбое сохранения.
`tests/test_portfolio.py` проверяет переход после сохранения, список и карточки,
общий календарь двух покупок, независимые параметры, закрытую историю и перезапуск.
`tests/test_nbu.py` проверяет JSON-контракт, новый запрос при каждом поиске, ошибки и автозагрузку без сети.
Прямой доступ к SQLite
ограничен `tests/test_db_storage.py`, где проверяются инициализация, совместимость
схемы и закрытие соединений, составные внешние ключи и сохранность несовместимого файла.

Описание требований и изменений хранится в `openspec/`, контекст проекта и правила работы — в `openspec/config.yaml`.
