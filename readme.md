# Трекер ОВДП

Небольшой пет-проект для личного учёта облигаций внутреннего государственного займа Украины (ОВДП). Помогает отслеживать покупки, погашения и прибыль, а также планировать будущие вложения.

Планируемые возможности:

- Добавление облигаций с датой покупки, стоимостью, количеством и датой погашения.
- Учёт полученных выплат и расчёт ожидаемой прибыли.
- Статистика прибыли и доходности за выбранные периоды.
- Планирование будущих покупок и ожидаемых поступлений.

Проект рассчитан на одного пользователя. Приоритет — простые и понятные решения, минимум зависимостей и архитектуры, только необходимой для текущих задач.

## Текущее состояние

Реализован минимальный каркас Flask/Jinja: главная страница, локальный CSS и
схема SQLite версии 1 для банков, пакетов, расписания, фактических выплат и продаж,
точный разбор денежных строк до сотых и вычисление сумм операций.
Форма покупки сохраняет параметры пакета и расписание купонов/погашения одной транзакцией.
Просмотр портфеля, продажи, подтверждения выплат и расчёты доходности пока не реализованы.

Первый запуск создаёт пустую базу `instance/portfolio.sqlite3` в корне проекта,
без демонстрационных операций. Файл данных исключён из Git. Повторный запуск
сохраняет данные. При неизвестной версии схемы приложение отказывается от запуска
с объяснением причины и не перезаписывает базу.
При размещении проекта в `D:\Projects\OVDPCalculator` полный путь данных —
`D:\Projects\OVDPCalculator\instance\portfolio.sqlite3`; он не зависит от текущего
каталога запуска. Правило `instance/` в `.gitignore` исключает весь каталог данных.

## Установка и запуск

Требуется Python 3.11 с pip. Команды выполняются из корня проекта, например
`D:\Projects\OVDPCalculator`. Создавать virtualenv или устанавливать Docker не нужно.

Установите зафиксированные зависимости в используемый Python:

```powershell
python -m pip install -r requirements.txt
```

Для первоначальной загрузки зависимостей нужен интернет. После установки приложение
работает без интернета: шаблоны и стили находятся в пакете, внешние сервисы и CDN не используются.

Запустите приложение:

```powershell
python -m ovdp_calculator
```

Откройте [http://127.0.0.1:5000/](http://127.0.0.1:5000/) в браузере. Должна появиться
страница «Трекер ОВДП» со ссылкой «Добавить покупку».
Сервер слушает только `127.0.0.1:5000`; debug, интерактивный отладчик и автоматический
перезапуск выключены, в том числе при заданной переменной `FLASK_DEBUG`.

Чтобы завершить работу, нажмите `Ctrl+C` в терминале с запущенным приложением.

## Добавление покупки

На главной странице выберите «Добавить покупку». Форма подставляет текущую локальную
дату покупки, номинал 1000 и валюту UAH; эти значения можно изменить. Поддерживаются
UAH, USD и EUR. Укажите ISIN, название банка, цену одной облигации и целое положительное
количество. Номинал и цена должны быть положительными, купон на одну облигацию —
неотрицательным. Денежные поля принимают точку или запятую и максимум два знака после разделителя.

Введите купонные даты по одной в строке в формате `ГГГГ-ММ-ДД`. Погашение подставляется
по последней дате и следует за изменениями расписания до ручной правки поля погашения.
Без JavaScript последняя купонная дата используется при сохранении, если погашение не заполнено.
Для бескупонного пакета оставьте расписание пустым, укажите купон 0 и дату погашения вручную.

Исторические покупки и прошедшие даты расписания разрешены. Будущая дата покупки
не принимается; погашение должно быть не раньше покупки. Купонные даты должны быть
уникальны и находиться между покупкой и погашением включительно. Купон и погашение
в один день сохраняются отдельными событиями. Прошедшая дата не создаёт фактического поступления.

При ошибке форма сохраняет введённые значения и показывает причину рядом с полем.
Успешное сохранение подтверждается сообщением «Покупка сохранена».
Банк, пакет и всё расписание сохраняются вместе; при сбое частичных записей не остаётся.

## API хранения данных

Класс `Database` из `ovdp_calculator.db` хранит приватное соединение и содержит
SQL, схему SQLite и управление транзакциями. Остальной код получает экземпляр
явно и работает через его методы:

- `add_bank`, `get_bank`, `list_banks`, `delete_bank` — банки;
- `add_lot`, `get_lot`, `list_lots`, `delete_lot` — пакеты;
- `add_scheduled_payment`, `list_scheduled_payments` — плановые выплаты;
- `add_actual_payment`, `list_actual_payments` — подтверждённые выплаты;
- `add_sale`, `list_sales` — продажи.

Класс не зависит от Flask и не использует `g` или контекст приложения.
Методы возвращают обычные словари и списки.
`get_bank` и `get_lot` возвращают `None`, если запись не найдена; методы удаления
возвращают признак удаления. Списки выплат и продаж можно ограничить параметром `lot_id`.
`add_bank` обрезает крайние пробелы и повторно использует банк с тем же именем
без учёта регистра.

Каждая одиночная запись сохраняется автоматически. Для атомарного изменения
нескольких записей используется `with database.transaction():`; при исключении
вся группа откатывается. Соединение вызывающему коду не передаётся.
Ошибки ограничений выражаются через `db.DataIntegrityError`, остальные ошибки
SQLite — через `db.DatabaseError`, неизвестная версия — через `db.SchemaVersionError`.
API обеспечивает хранение, проверку формата денежных строк и ограничения схемы; расчёты портфеля и полная
проверка истории относятся к следующим задачам.

Вне HTTP жизненным циклом управляет контекстный менеджер:

```python
from ovdp_calculator.db import Database

with Database("instance/portfolio.sqlite3") as database:
    with database.transaction():
        bank = database.add_bank("Банк А")
```

При выходе соединение закрывается. `close()` можно вызвать явно и повторно;
использование закрытого экземпляра вызывает `DatabaseError`.

Для HTTP под декоратором маршрута добавляется `@with_database` из
`ovdp_calculator.web`. Обёртка создаёт отдельный экземпляр на каждый запрос,
передаёт его первым аргументом обработчику (`def index(database):`) и закрывает
при завершении, включая исключения. Обработчик вызывает методы полученного
объекта. При старте приложение проверяет схему отдельным краткоживущим экземпляром.

## Точность денежных значений

Модуль `ovdp_calculator.money` разбирает денежные строки через `parse_money`
непосредственно в `Decimal`, без промежуточного `float`. Допустимы точка или запятая
как десятичный разделитель, знак и пробелы по краям. Разделители тысяч, экспоненциальная
запись, нечисловые и бесконечные значения отклоняются с `ValueError`; числовые
объекты вместо строк также не принимаются.
Денежные значения допускают максимум два знака после разделителя. Лишние знаки,
включая завершающие нули, отклоняются без автоматического округления:
`1000,01` допустимо, `1000,005` и `1000,010` — ошибка.

Методы `Database` сохраняют номинал, цену покупки, купон, цену продажи и фактическую
сумму как точные десятичные строки в полях `TEXT`, с точкой и не более чем двумя
десятичными знаками. При записи исходные значения не округляются.

`operation_amount(unit_amount, quantity=1)` умножает `Decimal` на целое неотрицательное
количество и возвращает точную сумму с двумя знаками после запятой. При цене до
сотых и целом количестве дробных копеек не возникает. Для фактической суммы выплаты
используется количество 1. Агрегаты суммируют точные суммы операций.
В покупках и продажах количество должно быть целым положительным; функция расчёта
допускает также ноль для пустого остатка. Проверка положительности цены и суммы
относится к предметным операциям; денежные функции допускают отрицательные потоки и ноль.

Например, `operation_amount(parse_money("1000,01"), 3)` возвращает
`Decimal("3000.03")` без округления цены или результата.

## Проверки

Средство автоматического тестирования проекта — pytest. Установите зависимости
для разработки (они также включают зависимости приложения):

```powershell
python -m pip install -r requirements-dev.txt
```

Запустите весь набор из корня проекта:

```powershell
python -m pytest
```

Для подробного вывода добавьте `-v`, для отдельного файла — `tests/test_db.py`.
Конфигурация запуска хранится в `pytest.ini`. Новые тесты пишутся функциями
с `assert`, фикстурами и параметризацией pytest. Проверки используют временные
SQLite-файлы через `tmp_path` и не меняют рабочую базу.
`tests/test_db.py` проверяет публичный API без SQL и контекста Flask.
`tests/test_web.py` проверяет передачу и закрытие экземпляров в HTTP-обработчиках.
`tests/test_purchases.py` проверяет форму покупки, значения по умолчанию, допустимые
валюты и даты, точность сумм, расписание и откат при сбое сохранения.
Прямой доступ к SQLite
ограничен `tests/test_db_storage.py`, где проверяются инициализация, совместимость
схемы и закрытие соединений.

Описание требований и изменений хранится в `openspec/`, контекст проекта и правила работы — в `openspec/config.yaml`.
