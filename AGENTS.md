# Правила проекта

## Язык

- Комментарии и docstring в исходном коде и тестах пиши на английском языке.
- Тексты ошибок и сообщений исключений в коде и тестах пиши на английском языке.
- Документация проекта и артефакты OpenSpec могут оставаться на русском языке.

## Стиль кода

- Максимальная длина строки — 120 символов. Не разбивай выражения и вызовы,
  если целиком они помещаются в строку из 120 символов с учётом отступа.
- Между соседними функциями и методами оставляй ровно две пустые строки,
  в том числе между методами одного класса.
- Внутри функции разделяй логические блоки одной пустой строкой.
- Если функция содержит более одного логического блока, перед каждым блоком
  ставь однострочный комментарий на английском, объясняющий назначение блока.
- Каждый публичный метод класса должен иметь docstring на английском.
  Начинай текст с цели функции, затем описывай значимые входные параметры
  и возвращаемый результат. Если значимых параметров нет, не указывай отсутствие
  аргументов и не пиши «Accept no arguments». Если функция ничего не возвращает,
  не пиши «return None» и не добавляй секцию Returns только ради None.
  Для контекстных менеджеров описывай значимое выдаваемое значение и завершение контекста.
  Значимое None, например при отсутствии искомой записи, описывай как часть результата.

## Работа с базой данных

- Все SQL-запросы приложения, структура SQLite, соединения и настройка хранилища
  находятся в `ovdp_calculator/db.py`.
- Остальные модули используют высокоуровневые методы экземпляра `Database` для добавления,
  получения и удаления предметных данных. Не передавай им соединения, курсоры,
  `sqlite3.Row` или SQL-запросы; наружу возвращай обычные словари и списки.
- Одиночные операции записи сохраняются автоматически. Связанные изменения
  объединяй через `with database.transaction():`; этот контекст не возвращает соединение.
- Класс `Database` хранит приватное соединение и не зависит от Flask: не используй
  в `db.py` объекты `g`, `current_app` или контекст приложения.
- Передавай экземпляр `Database` в обработчики HTTP явно через `@with_database`
  из `ovdp_calculator/web.py`. Обёртка создаёт отдельный экземпляр на запрос
  и гарантирует закрытие при успехе и исключении. Не разделяй одно соединение
  между запросами. Вне HTTP используй `with Database(path) as database:`.
- Ошибки хранилища обрабатывай через исключения `db`, без зависимости от `sqlite3`.
- Финансовые расчёты и проверка согласованности истории остаются в предметных
  модулях; они получают экземпляр `Database` явно и работают через его методы.
- Обычные тесты данных проверяют публичный API. Прямой доступ к SQLite допустим
  только в отдельных низкоуровневых тестах хранилища, когда нужно смоделировать
  неизвестную схему или проверить внутреннее управление соединениями.

## Тестирование

- Используй pytest для всех автоматических тестов проекта.
- Новые тесты пиши функциями с обычными `assert`, фикстурами и параметризацией pytest.
- Зависимости для разработки и тестирования фиксируй в `requirements-dev.txt`.
- Установка: `python -m pip install -r requirements-dev.txt`.
- Запуск полного набора из корня проекта: `python -m pytest`.
- Тесты хранятся в `tests/`. Для SQLite используй временные файлы через `tmp_path`;
  рабочую базу из `instance/` в тестах не открывай и не изменяй.
